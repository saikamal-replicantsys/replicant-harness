# RepliSense Mapping

| Current RepliSense Capability | Harness Concept |
| --- | --- |
| Structured Python response | Output contract |
| Node validation | Schema sensor |
| SourceTraceabilityMap / chunk IDs | Evidence plus citation sensor |
| Provider layer | Provider routing |
| QC validation | Workflow sensors |
| Human reviewer | Escalation boundary |
| Prompt versions | Guide versions |
| Observability | Traces and metrics |
| Template section | Request contract section intent |
| Node normalization | Application-owned deterministic boundary |

## Interpretation

The harness does not replace RepliSense. It standardizes reliability concerns around the workflows RepliSense already has.

The most immediate value is shared vocabulary: guides, contracts, sensors, policies, traces, evaluations, and decisions.
