# Observability

Harness observability answers: what happened, why did it happen, and what evidence did the decision depend on?

## Trace Fields

- run ID
- trace ID where implemented
- attempt number
- provider
- model
- token estimates
- latency
- cost band
- sensor outcomes
- retry reason
- evidence IDs
- prompt or guide versions
- final decision

## Why This Matters

Regulated-document workflows need explainable operational behavior. A trace should make it possible to understand why a response was accepted, repaired, retried, blocked, or sent to human review.
